# Blog editorial guide

1. Start with the actual study or implementation goal and sources used.
2. Separate source availability, execution, measurement, and paper-reported values.
3. Name tools, boards, inputs, commands, and observed outputs only when supported.
4. Do not invent errors or troubleshooting narratives.
5. Separate verified, unverified, and next-verification sections.
6. Use the actual publication date and record later changes in `updated` and `revision_history`.
7. Keep translation key, numerical results, and evidence state synchronized across KO/EN pairs.
8. Keep unsupported steps as `planned` roadmap items without placeholder posts.
