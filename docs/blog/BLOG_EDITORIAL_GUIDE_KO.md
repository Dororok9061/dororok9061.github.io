# 블로그 편집 지침

1. 실제 수행 목적과 사용 자료를 먼저 적는다.
2. Source, 실행, 측정, 논문 보고 값을 분리한다.
3. 도구·board·입력·명령·관찰 결과를 확인된 범위에서만 쓴다.
4. 오류 기록이 없으면 시행착오를 만들지 않는다.
5. `확인한 내용`, `확인하지 못한 내용`, `다음 검증`을 구분한다.
6. 새 글은 실제 공개일을 `date`, 실제 수정일을 `updated`에 기록한다.
7. KO/EN pair는 translation key, 결과 수치, Evidence Status를 일치시킨다.
8. 빈 단계는 Roadmap의 `planned`로 두며 placeholder 글을 만들지 않는다.
